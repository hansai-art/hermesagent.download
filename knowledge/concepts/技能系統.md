「越用越聰明」聽起來像行銷詞。但在 Hermes 身上，它指的是一件很具體的事:**agent 會把自己摸索出來的做法存成技能(skill)，下次遇到類似任務直接調用**。

技能是 Hermes 的「程序性記憶」——跟[記憶系統](/concepts/記憶系統/)那種「事實記憶」不同，它記的是**一整套怎麼做的流程**，而且只在相關時才載入，平常不佔空間[^1]。

## agent 什麼時候會長出一個技能

Hermes 用 `skill_manage` 工具建立技能，通常發生在這幾種時刻[^2]:

- 成功完成一個複雜任務(5 個以上工具呼叫)
- 遇到錯誤或死路，然後解開了
- 發現一套非顯而易見的工作流
- 被你糾正了做法

換句話說，**它從「成功」和「踩坑」兩邊學**。你糾正它一次，那個教訓可能就變成一個技能，下次不再犯。

管理技能的動作有 `create`、`patch`(偏好用這個做小修正)、`edit`、`delete` 等[^3]。跟記憶一樣，可以設 `skills.write_approval: true` 讓所有寫入先暫存到 `~/.hermes/pending/skills/` 等你審核[^4]。

## 一個技能長什麼樣

技能是 `SKILL.md` 檔案，有標準的 frontmatter[^5]:

```yaml
---
name: my-skill
description: 簡短描述(≤60 字元)
version: 1.0.0
platforms: [macos, linux] # 選填:限定作業系統
metadata:
  hermes:
    tags: [category, tags]
    requires_toolsets: [terminal]
---
```

內容依固定順序寫:**When to Use(何時用)→ Procedure(步驟)→ Pitfalls(陷阱)→ Verification(驗證)**[^6]。看得出來這套結構跟寫一篇好的操作文件很像——因為技能本質上就是 agent 寫給自己看的操作手冊。

技能存在 `~/.hermes/skills/`，依分類分子目錄[^7]。一個技能可以不只是一個檔案，還能帶 `references/`、`templates/`、`scripts/`、`examples/` 等資料夾[^8]。

## 內建 vs 選配

- **內建技能(bundled)**:隨 Hermes 一起安裝，自動種進 `~/.hermes/skills/`。更新時，你沒改過的會跟著更新，**你改過的會被保護不覆蓋**[^9]。
- **選配技能(optional)**:用指令安裝，例如 `hermes skills install official/security/1password`[^10]。

想從零開始、不要任何內建技能，安裝時加參數(這行是官方安裝腳本，網址是官方網域):

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash -s -- --no-skills
```

或事後 `hermes skills opt-out`[^11]。

## 進步揭露:為什麼技能多也不吃 token

技能一多，不是全部塞進上下文——Hermes 用「進步揭露」(progressive disclosure)分三層載入[^12]:

| 層級 | 動作 | 成本 |
|---|---|---|
| Level 0 | 列出所有技能的名稱與描述 | 約 3k token |
| Level 1 | 載入某個技能的完整內容 | 視情況 |
| Level 2 | 載入技能裡的特定參考檔 | 視情況 |

平常只帶著一份輕薄的清單，真的要用某個技能才把它完整讀進來。所以你裝一百個技能，平常也不會拖慢它。

## Skills Hub:不只用自己長的

除了 agent 自己建的，你也能從社群裝現成技能。Hermes 的 Skills Hub 聚合多個來源[^13]:

```bash
hermes skills browse                    # 瀏覽全部
hermes skills search kubernetes         # 搜尋
hermes skills inspect openai/skills/k8s # 安裝前預覽
hermes skills install official/security/1password
```

來源包含官方(`official`，內建信任)、Vercel 的公開目錄(`skills-sh`)、GitHub repo、社群市集等[^14]。

⚠️ **所有 Hub 安裝都會過安全掃描**[^15]。這很重要——技能是會被 agent 執行的程序，裝來路不明的技能等於讓陌生程式碼在你的環境裡跑。`inspect` 先看過再裝是好習慣。

技能遵循 **agentskills.io 開放標準**[^16]，所以可以跨相容的 agent 系統攜帶、分享。

## 教它一個新技能

你也可以主動叫它學:

```text
/learn the REST client in ~/projects/acme-sdk
/learn https://docs.example.com/api/quickstart
/learn how I just deployed the staging server
```

`/learn` 讓它從一段程式碼、一份文件、或你剛做過的一件事，提煉出一個可重用的技能[^17]。

## 這跟記憶有什麼不同

容易搞混，一句話分清楚:

- **記憶**記「事實」——你是誰、專案長怎樣(小、常駐)
- **技能**記「怎麼做」——一整套操作流程(可大、要用才載入)

兩者合起來，就是官方說的「閉環學習」:經驗變成技能與記憶，下次用得上，用的過程再修正。

## 常見問題

### agent 自己建的技能會亂建嗎?

它有觸發條件(通常是完成複雜任務或解開錯誤後)，不是每句話都建。不放心可以開 `write_approval` 審核。

### 技能可以分享給團隊嗎?

可以。用 `hermes skills publish` 發佈，或設定 `external_dirs` 指向共用目錄[^18]。

### 內建技能佔太多，想清掉?

`hermes skills opt-out --remove` 會刪掉你沒改過的內建技能[^19]。
