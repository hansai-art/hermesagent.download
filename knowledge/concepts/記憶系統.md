你可能以為「Hermes 有記憶」代表它把你們的每一句話都記著。其實不是：而且理解它「不記什麼」，比理解它「記什麼」更有用。

Hermes 的記憶分成兩層：一個**很小、永遠帶在身上**的核心，和一個**無限大、要用才去翻**的檔案庫。搞懂這個分工，你就知道該把重要的事情放進哪一層。

## 第一層：小而精的核心記憶

Hermes 在 `~/.hermes/memories/` 放兩個檔案[^1]:

| 檔案 | 上限 | 記什麼 |
|---|---|---|
| `MEMORY.md` | 2200 字元(約 800 token) | 環境事實、專案慣例、工具怪癖與 workaround、完成的任務、有效的技巧[^2] |
| `USER.md` | 1375 字元(約 500 token) | 你的名字、角色、時區、溝通偏好、工作習慣、技術程度[^3] |

**為什麼故意設這麼小？** 因為這兩個檔案會在每次對話開始時**一次性注入系統提示，然後整場對話都不再改變**：官方稱為「凍結快照模式」(frozen snapshot pattern)，目的是保住 LLM 的 prefix cache 效能[^4]。記憶塞太多，等於每次對話都拖著一大包東西，又慢又貴。

所以這一層的邏輯是：**只留「每次對話都該知道」的精華**。大段的程式碼、log、資料表會被明確跳過：「太大了，不適合放記憶」[^5]。

## agent 怎麼更新這一層

Hermes 用三個動作管理記憶：**add(新增)**、**replace(以子字串比對替換)**、**remove(移除)**[^6]。

注意：**沒有 read 動作**，因為記憶本來就會自動注入系統提示，agent 隨時「看得到」，不需要特地去讀[^7]。

如果你不想讓它自由寫入，可以在 `~/.hermes/config.yaml` 開啟審核：

```yaml
memory:
  memory_enabled: true
  write_approval: false # 預設 false，自由寫入
  memory_char_limit: 2200
  user_char_limit: 1375
```

把 `write_approval` 設成 `true`，每次寫入會先暫存，用 `/memory pending` 審核後才進檔案[^8]。

## 第二層：無限大的對話檔案庫

核心記憶塞不下的東西去哪了？**還在**：在你過去所有對話的完整紀錄裡。

Hermes 用 `session_search` 工具去搜尋這些歷史對話。它查的是 SQLite 資料庫(`~/.hermes/state.db`)的 FTS5 全文索引，容量「無限」、查詢約 20 毫秒[^9]。

這一層有個關鍵特性容易被誤解：**它回傳的是資料庫裡的原始訊息，不做 LLM 摘要、不截斷**[^10]。也就是說，你三個月前講過的話，它翻出來是**逐字原文**，不是模型憑印象重述的版本。這比「摘要」可靠得多。

## 這對你的實際意義

理解這兩層，你就知道怎麼「餵」它：

- **希望它每次都記得的**(你的偏好、專案慣例)→ 明確告訴它，讓它寫進核心記憶。因為空間小，講重點。
- **偶爾要翻的細節**(某次怎麼解某個 bug)→ 不用刻意記，它留在對話紀錄裡，需要時用 `session_search` 撈得回來。
- **一大包資料**(整份 log、完整檔案)→ 別期待它「記住」，那不會進記憶。需要的話讓它當下去讀。

## 記憶 vs 上下文檔案

Hermes 還有另一種「記憶」叫上下文檔案(context files)，例如 `SOUL.md`、`AGENTS.md`。差別在[^11]:

- **記憶(MEMORY.md / USER.md)**:agent 自己策展、有大小上限、會演變
- **上下文檔案**：你手動維護、內容固定，是你給 agent 的設定而非它的觀察

簡單說：記憶是「它學到的」，上下文檔案是「你交代的」。

## 常見問題

### 換一台電腦，記憶會跟著走嗎？

記憶存在本機的 `~/.hermes/memories/`。換電腦用 `hermes backup` 打包再到新機器 import，記憶會一起搬，見 [換電腦：搬到新機器](/migrate/move-to-new-machine/)。

### 記憶滿了會怎樣？

有字元上限，agent 會自己取捨：用 replace 更新舊的、remove 過時的。這也是為什麼它只留精華。

### 我可以直接編輯 MEMORY.md 嗎？

可以，它就是純文字檔。但下次 agent 也可能改動它，你的手動編輯不保證永久保留。重要的偏好，不如直接講給 agent 聽讓它寫進去。
