在中文社群搜 Hermes Agent，你會先撞到一排這種標題：「丟掉你的龍蝦！」「把龍蝦 OpenClaw 打回寒武紀」[^1][^2]。看起來像是有個東西把另一個東西殺掉了。

先講結論。截至 2026 年 7 月 29 日，龍蝦活得好好的，GitHub 星數還是 Hermes Agent 的 1.7 倍[^3][^4]。「龍蝦殺手」也不是完全空穴來風，但站得住的架構差異只有兩個，而最常被當成殺手鐧的那一個（跑在哪裡跟從哪裡指揮是分開的）兩邊都做得到。這篇把稱號拆成四段：誰是龍蝦、誰在喊殺手、真正差在哪，以及哪些部分被誇大了。

## 「龍蝦」是 OpenClaw 自己選的稱號

龍蝦不是外號，是 OpenClaw 官方 repo 的自我介紹。它的 GitHub 描述欄原文只有一句：

> Your own personal AI assistant. Any OS. Any Platform. The lobster way. 🦞[^4]

（你自己的個人 AI 助理。任何作業系統，任何平台。用龍蝦的方式。）

所以中文圈說的「養龍蝦」「龍蝦」，指的一律是 OpenClaw 這個開源 AI agent 專案，跟 Hermes Agent 是兩個不同團隊的不同產品。

順帶更正一個中文媒體常見的錯誤：**OpenClaw 不是 Anthropic 的產品，也不是 Claude Code**。動區的報導把它寫成「Anthropic 的 Claude Code 產品」[^2]，這是錯的。OpenClaw 是獨立開源專案，作者 Peter Steinberger 在 2026 年 2 月加入 OpenAI，但專案本身維持 MIT 授權獨立運作，並沒有被收購[^5][^6]。

## 「殺手」是中文媒體下的標，不是官方定位

Nous Research 官方從來沒有拿 OpenClaw 當對手宣傳。Hermes Agent 的 repo 描述只有五個字：「The agent that grows with you」（會跟著你一起長大的 agent）[^3]。官方文件的主打是「閉合的學習迴圈（closed learning loop）」[^7]，通篇沒有比較對象。

「殺手」的說法來自中文媒體與 AI 網紅。《創業小聚》2026 年 4 月的報導把這個現象講得很清楚：

> 在開源 AI 助理 OpenClaw（龍蝦）爆紅後，最近 GitHub 上出現一個名為 Hermes Agent 的自主 AI 框架專案，在發布後一個多月內便迅速吸引超過 7 萬顆星星關注，更有多位 AI 網紅與媒體宣稱「比龍蝦更強」或「丟掉你的龍蝦」[^1]

換句話說，這是一個社群造出來的標籤。你可以拿它當入口，但不要拿它當技術結論。

## 真正的差異：一個是結構性的，一個是預設值

去掉行銷語之後，站得住的差異比媒體講的少。以下兩條查證後確認；第三條「跑在哪裡跟從哪裡指揮是分開的」常被寫成 Hermes Agent 的殺手鐧，其實兩邊都做得到，放到下一段一起拆。

### 一、技能是長出來的，不是寫出來的

這是最核心的一條。兩邊都有技能（skill）機制，差別在技能從哪裡來。

OpenClaw 的技能主要靠人寫好、發布到 ClawHub 市集，使用者再去裝，市集規模到 2026 年初已有數千個項目[^8]。Hermes Agent 的技能是 agent 自己從經驗裡建立的：官方稱之為程序性記憶，agent 摸索出一套可行流程之後把它存成技能，之後在使用中持續自我改良[^13]。官方文件的原文是「creates skills from experience, improves them during use」（從經驗建立技能，在使用中改良它們）。

實際差別：OpenClaw 你要先知道自己缺什麼技能，再去找；Hermes Agent 是你用得愈久，它自己補得愈多。細節見[技能系統](/concepts/技能系統/)。

### 二、記憶差在預設值與資料去向，不是差在「有沒有」

兩邊都有跨 session 記憶，這點不構成差異：OpenClaw 的 session 預設不會自動重置，跨 Gateway 重啟仍沿用同一個 `sessionId`[^16]。差別在三個預設值。

Hermes Agent 預設把所有 CLI 與訊息平台的對話寫進本機 SQLite，用 FTS5 全文檢索，官方文件明寫查詢「回傳資料庫裡的真實訊息，不做 LLM 摘要、不截斷」[^14]。這是開箱行為，不是要自己打開的功能：本站在一台從未調整過記憶設定的機器上跑 `hermes sessions stats`，得到 260 個 session、23,627 則訊息、566.9 MB 的資料庫。外部記憶供應商是選配的第三層，`hermes memory` 這個子指令的說明就是「Configure external memory provider」（設定外部記憶供應商），不設定也能用。

OpenClaw 這一側，記憶檢索預設是開的（`memory.search.enabled` 預設 `true`），但預設不索引對話記錄：`memory.search.sources` 預設值是 `["memory"]`，官方文件明寫「Session indexing is opt-in」（對話索引要自己開啟）[^15]。檢索供應商 `memory.search.provider` 預設是 `openai`，也就是預設走外部服務做嵌入運算，而且遠端供應商不可用時是 fail closed，不會自動退回本機全文檢索[^15]。回傳的是片段，`maxSnippetChars` 預設 450 字[^15]。跨對話回憶 `rememberAcrossConversations` 在個人安裝預設開啟，設了 DM 隔離則關閉[^15]。

一句話講完：Hermes Agent 預設「全部存本機、撈回完整原文」，OpenClaw 預設「只檢索記憶檔、對話索引自己開、經外部供應商、回傳 450 字片段」。功能清單上兩邊都寫得出「跨 session 記憶」，差的是預設值；在意資料不出本機的人，這個差別比功能清單重要。細節見[記憶系統](/concepts/記憶系統/)。

## 技能安全：差別在流程，不在誰比較乾淨

這是「龍蝦殺手」說法裡最有份量的一塊，但也最容易被寫歪。

OpenClaw 的技能市集 ClawHub 出過大事。資安公司 Koi Security 稽核了 2,857 個 ClawHub 技能，找出 341 個惡意項目，接近整個市集的 12%，其中 335 個屬於同一個代號 ClawHavoc 的協同攻擊行動，手法包含竊取資料、植入後門與安裝竊密軟體[^8]。OpenClaw 後續在 2026 年 2 月與 VirusTotal 合作，對上架技能做自動掃描[^9]。

**但這不是「Hermes Agent 沒有這個問題」。** Hermes Agent 一樣有 Skills Hub，一樣能從 Vercel 的公開目錄、GitHub repo 與社群市集裝第三方技能[^10]。技能是會被 agent 直接執行的程式碼，只要允許第三方來源，供應鏈攻擊面就存在。

真正的差別在預設流程：Hermes Agent 提供安裝前預覽指令，讓你先看過內容再決定裝不裝。

```bash
hermes skills inspect openai/skills/k8s
```

所有 Hub 安裝都會過安全掃描[^10]。而 ClawHub 的自動掃描是在 341 個惡意技能被抓出來之後才補上的[^8][^9]。這是「一開始就設計進去」與「出事之後補」的差別，值得知道，但不等於裝了 Hermes Agent 就免疫。

## 哪些部分被誇大了

一篇只講優點的比較文對你沒有用。以下是查證後不支持「殺手」敘事的部分。

**「跑在哪裡跟從哪裡指揮是分開的」不是 Hermes Agent 獨有。** 這一條最常被寫成殺手鐧，但 OpenClaw 的自我介紹本來就是「Any OS. Any Platform.」（任何作業系統，任何平台）。它的 README 點名支援的頻道超過二十個，包含 WhatsApp、Telegram、Slack、Discord、Signal、iMessage、SMS、IRC、Microsoft Teams、Matrix、Feishu、LINE、QQ 等，另有 CLI、macOS app、iOS 與 Android node、Windows Hub；執行面預設跑在本機，非 main session 可以丟進沙箱，後端有 Docker（預設）、SSH 與 OpenShell，也支援透過 SSH 遠端控制 gateway[^4]。Hermes Agent 這一側是六種執行後端（local、Docker、SSH、Daytona、Singularity、Modal）與 20 多個平台入口[^7]。真正的差別只剩後端清單：Hermes Agent 多了 Modal 這類無伺服器與 Daytona、Singularity 這類受管沙箱。訊息平台的數量上，OpenClaw 點名的反而更多。

**龍蝦沒有被殺，而且比較大。** 2026 年 7 月 29 日的 GitHub 數據[^3][^4]：

| | Hermes Agent | OpenClaw |
|---|---|---|
| 星數 | 221,928 | 384,437 |
| Fork 數 | 42,476 | 80,776 |
| 未關閉 issue 與 PR | 25,988 | 6,458 |
| 專案建立 | 2025-07-22 | 2025-11-24 |
| 授權 | MIT[^3] | MIT 條文[^11] |

OpenClaw 比 Hermes Agent 晚四個月開張，星數卻多出七成以上。

**未處理的問題堆得比較高。** 上表最後一欄值得單獨看：Hermes Agent 未關閉的項目是 OpenClaw 的四倍。這個數字要小心解讀，GitHub API 的 `open_issues_count` 把未合併的 PR 一起算進去，所以它同時反映「問題多」與「貢獻多」，不能單獨拿來當品質指標。但無論怎麼解讀，「Hermes Agent 比較成熟穩定」這個推論，這份數據支持不了。

**中文媒體的數字大多過期。** 《創業小聚》寫的「超過 7 萬顆星」是 2026 年 4 月的狀態[^1]，動區寫的 69,900 顆星也是同一時期[^2]。四個月後這個數字是 22 萬。看到中文報導引用的數字，一律回去對 GitHub 原始資料。

**兩邊都是開源，不是零和。** Hermes Agent 的授權是 MIT[^3]。OpenClaw 的 LICENSE 檔內容是標準 MIT 條文（著作權人為 OpenClaw Foundation），只是 GitHub 的自動判定把它歸為 Other 而非 MIT[^11]，要精確引用授權時以 repo 內的 LICENSE 檔為準。你不需要選邊站，Hermes Agent 甚至內建了官方的 OpenClaw 遷移技能，資料搬得過去[^12]。

## 那我該用哪一個

| 你的情況 | 建議 |
|---|---|
| 想要 agent 用愈久愈懂你的專案慣例 | Hermes Agent，學習迴圈是它的主場 |
| 需要人在外面用手機指揮遠端的 agent | 兩邊都做得到，這一條不構成選擇理由 |
| 要求對話記錄不離開自己的機器 | Hermes Agent，本機 FTS5 是預設；OpenClaw 檢索預設走外部供應商 |
| 已經在用 OpenClaw 而且跑得順 | 不必急著搬，先看[遷移指南](/migrate/migrate-from-openclaw/)評估成本 |
| 主要看社群規模與現成技能數量 | OpenClaw 目前仍然比較大 |

## 常見問題

### Hermes Agent 跟 OpenClaw 差在哪？

主要差在兩件事。第一，技能的來源不同：Hermes Agent 的技能由 agent 從使用經驗自己建立並持續改良，OpenClaw 的技能主要靠人寫好、發布到 ClawHub 市集再安裝[^8][^13]。第二，記憶的預設值不同：Hermes Agent 預設把所有對話寫進本機 SQLite，用 FTS5 回傳完整原文；OpenClaw 預設不索引對話記錄，要自行開啟，且檢索預設走外部供應商、回傳 450 字片段[^14][^15]。訊息平台與遠端執行兩邊都支援，不構成差異。

### OpenClaw 也有跨 session 記憶嗎？

有。OpenClaw 的 session 預設不會自動重置，跨 Gateway 重啟仍沿用同一個 `sessionId`，也提供跨對話回憶（個人安裝預設開啟）[^16][^15]。差別在預設值：OpenClaw 的 `memory.search.sources` 預設只有 `["memory"]`，對話索引官方標示為 opt-in，需要自己加上 `sessions`[^15]。Hermes Agent 則是預設就把對話全部索引在本機。

### Hermes Agent 的訊息平台支援比 OpenClaw 多嗎？

沒有，OpenClaw 點名的更多。OpenClaw 的 README 列出超過二十個頻道，包含 WhatsApp、Telegram、Slack、Discord、Signal、iMessage、SMS、IRC、Microsoft Teams、Matrix、Feishu、LINE、QQ 等，另有 CLI、macOS app、iOS 與 Android node 與 Windows Hub[^4]；Hermes Agent 官方文件寫的是 20 多個平台入口[^7]。兩邊都能做到「agent 跑在遠端、人用手機指揮」。

### Hermes Agent 跟 OpenClaw 哪一個社群比較大？

OpenClaw 比較大。2026 年 7 月 29 日的 GitHub 數據顯示 OpenClaw 有 384,437 顆星、80,776 個 fork，Hermes Agent 為 221,928 顆星、42,476 個 fork[^3][^4]。OpenClaw 比 Hermes Agent 晚四個月開張，星數仍多出七成以上。中文媒體引用的「7 萬顆星」是 2026 年 4 月的舊數字[^1]。

### 「龍蝦殺手」是官方說法嗎？

不是。「龍蝦殺手」是中文媒體與 AI 網紅使用的標題語[^1]，Nous Research 官方文件與 GitHub repo 描述都沒有提到 OpenClaw，也沒有拿它當比較對象[^3][^7]。至於「龍蝦」則是 OpenClaw 自己選的，出自它 repo 描述欄的原文「The lobster way. 🦞」[^4]。

### OpenClaw 被 OpenAI 收購了嗎？

沒有。OpenClaw 作者 Peter Steinberger 於 2026 年 2 月 15 日加入 OpenAI，但那是個人聘僱，不是收購[^5][^6]。OpenClaw 專案本身維持 MIT 授權獨立運作，程式碼與治理都沒有移轉給 OpenAI。

### Hermes Agent 跟 OpenClaw 可以同時安裝嗎？

可以，兩者是各自獨立的程式，不會互相覆蓋。但它們都會讀寫本機檔案並執行指令，同時運行時要分開管理權限範圍與 API 金鑰。Hermes Agent 另外內建官方的 OpenClaw 遷移技能，需要時可以把資料搬過去[^12]。
